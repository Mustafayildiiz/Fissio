# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Fissio: smart receipt processing and micro-expense management (Turkish-language UI/comments). Monorepo with three backend microservices (Docker Compose) and a Flutter mobile app. Note: README.md is now UTF-8 (was cp1254; converted).

## Commands

Backend (repo root; copy `.env.example` to `.env` for config, defaults work for dev):
- `docker compose up --build` — starts postgres, auth (host :8081), expense (:8082), ocr. Postgres and **ocr are internal-only** (no host port: the OCR service has no authentication; expense reaches it at `http://ocr:8080`; for local debugging add a `docker-compose.override.yml` with `ports: ["127.0.0.1:8083:8080"]`). OCR enforces input limits (15 MB / `OCR_MAX_IMAGE_PIXELS` 25 MP, `OCR_MAX_CONCURRENT` inferences), all services have healthchecks + `restart: unless-stopped`, expense waits for auth's healthcheck (auth owns `auth.sessions`). Schema comes from `db/init.sql` (runs only on first volume init).
- Go services (`services/auth`, `services/expense`, Go 1.25, gin + lib/pq + golang-jwt): from the service dir, `go test ./...`; single test: `go test -run TestName ./...`. Both have tests (`auth`: `unit_test.go` + PG-gated `auth_pg_test.go`; `expense`: `*_test.go`; `realreceipts_test.go` holds real PaddleOCR outputs whose assertions — e.g. BIM Koltuk = 17 items, PATITO ×2, no review — lock in deliberate parser behaviour). `integration_pg_test.go` (migration + HTTP flow incl. learned rules) is skipped unless `FISSIO_TEST_DATABASE_URL` points at a throwaway Postgres whose URL contains "test" — it DROPs the `expense` schema (e.g. `docker run -d -e POSTGRES_PASSWORD=t -e POSTGRES_DB=fissio_test -p 55432:5432 postgres:16-alpine`, then `FISSIO_TEST_DATABASE_URL=postgres://postgres:t@localhost:55432/fissio_test?sslmode=disable go test -run PG ./...`). The PG-gated suites (`auth_pg_test.go`, `integration_pg_test.go`, `isolation_pg_test.go`, `internal_pg_test.go`, budgets/avatar `*_pg_test.go`) all use the same `FISSIO_TEST_DATABASE_URL`; the auth suite DROPs `auth`, the expense suites DROP `expense`, so run the auth and expense suites one after the other, never in parallel. Neither service touches the other's schema any more: the auth tests use a `fakePurger` (expense's internal purge API) and the expense tests an in-memory `fakeAuth` HTTP server (`fakeauth_test.go`, auth's internal sessions API), so there is no raw DDL copy of the other service's tables.
- OCR service (`services/ocr`, Python 3.11, FastAPI): `pytest tests/`; run locally with `uvicorn app:app --port 8080`. Tests don't need paddleocr (imported lazily) but need numpy/opencv; the host Python usually lacks them, so run them in the built image with the source mounted: `docker run --rm -v "<repo>/services/ocr:/app" -w /app fissio-ocr:latest python -m pytest tests/ -q -p no:cacheprovider` (Git Bash: prefix `MSYS_NO_PATHCONV=1`, use `$(pwd -W)`). The image bakes code in via `COPY`, so the running service only picks up changes after `docker compose up --build`.

Mobile (`fissio_mobile/`): `flutter pub get`, `flutter run`, `flutter test`, single test: `flutter test test/ocr_engine_test.dart`, `flutter analyze`. Don't run `dart format` on existing files: the code is written with ~100-column lines and no formatter `page_width` is configured, so it reflows whole files to 80 columns.

## Architecture

- **auth** (Go, files `config/jwt/otp/mailer/sessions/ratelimit/account/handlers/main.go`): register → 6-digit email OTP (`auth.email_otps`, HMAC-hashed, 10 min `OTP_TTL_MINUTES`, ≤5 attempts, 60 s resend cooldown, ≤5/hour) → `verify-email` opens the first session; an unverified account cannot log in (login answers `403 email_not_verified` and re-sends a code only when the password was right). Tokens: 15-minute access JWT (`sub`, `sid`, `typ=access`, `JWT_ACCESS_SECRET`, falls back to `JWT_SECRET`) + opaque 30-day refresh token stored HMAC-hashed (`JWT_REFRESH_SECRET`) in `auth.refresh_tokens`, rotated on every use; a used token presented after a 45 s grace window revokes the whole session (theft detection). `auth.sessions` tracks device/platform/last activity; endpoints: `refresh`, `logout`, `logout-all`, `GET /auth/sessions`, `DELETE /auth/sessions/:id`, `forgot-password` (always 202) / `reset-password` (code, revokes all sessions), `DELETE /auth/account` (password confirmation; marks `auth.users.deleting_at` and revokes every session in one tx — login is then refused — then calls expense's internal `DELETE /internal/users/:id` via `userPurger`/`httpPurger` (`internal.go`) and only after a 2xx deletes the `auth.*` rows; if expense is unreachable it answers `202 {status: deletion_pending}` and `runDeletionSweeper` (every minute, `deletionSweepGrace` 30 s) finishes it; a best-effort second purge 15 s after success covers writes that slipped through expense's 10 s session cache; **auth never runs SQL against `expense.*`**). Mail: `Mailer` interface, SMTP via `SMTP_HOST/PORT/USER/PASS/FROM`; **empty `SMTP_HOST` = dev fallback that logs the code** (`docker compose logs auth | grep DEV-OTP`; codes are never returned by the API). In-memory per-IP limiter (`handler.rateMax`, tests raise it). Existing users are treated as verified by `migrate()` (backfill happens only when `email_verified_at` is first added). Schema lives in `migrate()` (`db/init.sql` only creates the schemas).
- **expense** (Go): validates the access JWT itself (`jwt.go`; `JWT_ACCESS_SECRET`/`JWT_SECRET` must match) and checks that its `sid` is alive AND owned by the token's `sub` through auth's internal API `GET {AUTH_INTERNAL_URL}/internal/sessions/:sid` (`sessionChecker`, 10 s cache; auth unreachable/5xx/wrong token = 503 `auth_unavailable`, never cached), so logout/remote logout/account deletion take effect within ~10 s. **Internal APIs** (both services): a second listener on `INTERNAL_PORT` (default 9090, NOT published in docker-compose) guarded by the shared `INTERNAL_TOKEN` (`X-Internal-Token`, constant-time compare, empty token rejects everything; both services refuse to start without it): auth serves `GET /internal/sessions/:sid` → `{alive, user_id}`, expense serves `DELETE /internal/users/:id` (`internal.go`; `userOwnedTables` lists every `expense.*` table with `user_id` and `TestPGUserOwnedTablesAreAllPurged` fails if a new one is forgotten), so logout/remote logout/account deletion take effect within ~10 s instead of at token expiry. **User → Profiles → Receipts**: `expense.profiles(user_id, name, client_uid)`, `expenses.profile_id` (BIGINT FK, the old unused text column is kept as `profile_id_legacy`) and `expenses.client_uid` (UNIQUE per user; existing rows got `srv-<id>`). `GET /profiles` creates the default "Kişisel" profile under an advisory lock when the account has none; every query is scoped by `user_id` and cross-account/profile access returns 404. `POST /expenses` is idempotent on `client_uid` (200 + existing row); `POST /expenses/bulk` (≤500, ≤10 MB body, per-item `created|skipped|error`; every receipt is written under its own SAVEPOINT so one row the DB rejects becomes an `error` instead of a 500 for the whole batch; `validate()` strips NUL/control characters) serves the offline queue and backup import. `profile_id` is optional on create (default profile) and filters list/summary. Routes at the root (no `/api` prefix) in `main.go`: categories, `receipts/parse` (text → structured fields via `parser.go`), `receipts/scan` (multipart, repeated `file` = pages of one long receipt, ≤6 pages/≤5MB each → OCR per page → `mergePageTexts` in `merge.go` (drops a seam only when ≥2 consecutive lines match: amounts must be identical, text matches via Levenshtein, Jaro-Winkler or left-cropped suffix) → one parse), expenses CRUD, `expenses/:id/images` (upload/get/delete receipt photos, stored as bytea in `expense.receipt_images`, ownership checked via JOIN on the expense's `user_id`), `reports/summary`. Direct `database/sql` access in `db.go`/`handlers.go`; CORS handled by hand in `main.go`.
- **ocr** (Python): receipt OCR using Strategy + Factory Registry (`ocr/base.py`, `factory.py`, `paddle_engine.py`, `custom_engine.py`, `config.py`). Engine chosen per request via `?engine=`, `X-OCR-Engine` header, or `OCR_ENGINE` env (default `paddleocr`, PP-OCRv4 mobile, `OCR_LANG=tr`). Endpoint: `/ocr/extract` (base64 image JSON, also multipart). Post-processing in `postprocess.py`: glyph fix, `dedupe_blocks` (NMS on overlapping same-text boxes, plus dropping fragment boxes contained in a full-line box), then `paddle_engine._reconstruct_receipt_lines` groups blocks into rows (slope-corrected) and orders each row left-to-right.
- **Auto-categorization** (`categorizer.go`, `category_lexicon.go`, `rules.go`): hybrid, pure functions, run inside `ParseWith` (`Parse` = `ParseWith` with no options). Taxonomy is the fixed 11-category set seeded/migrated in `db.go` (`migrateTaxonomy` renames the old names and merges Ulaşım into Akaryakıt / Ulaşım); the engine keys everything on `catKey` via `categoryKeyOf(name)` so old and new category names both work. Merchant layer: user rule (0.98) > header brand (0.9) > body-only brand (0.6); brands come from the code lexicon plus the `categories.keywords` column (`enrichCats`). Item layer (`classifyItem`): user item rule > lexicon (exact 0.9 / suffix-tolerant prefix 0.8 / truncated 0.7 / fuzzy 0.65; ties broken by a confident merchant context, e.g. ÇAY at a café vs market) > inherit the confident merchant's category (0.6, source `merchant`) > `Diğer` + `category_review`. Receipt category: confident merchant (≥0.85) wins even for mixed receipts (items keep their own categories), otherwise weighted vote (`amount × confidence`, × coverage, cap 0.85), below `categoryMinConfidence` (0.5, env `CATEGORY_MIN_CONFIDENCE`) falls back to `Diğer` with `category_needs_review` (separate from the total-mismatch `needs_review`). Learning: `POST/PUT /expenses` accept `suggested_category_id` (receipt and per item); when it differs from the saved `category_id`, `collectRuleUpdates` upserts a per-user row in `expense.category_rules` in the same transaction (keys from `merchantKey`/`normalizeKey`, ≤2000 per user); `loadRules` feeds them back into `ParseWith`; `GET /category-rules`, `DELETE /category-rules/:id`. Items persist only `{name, amount, category_id}` in the JSONB (`itemsForStorage`). Mobile: the draft keeps the scan's suggestion (`suggestedCategoryId`), `ReceiptDraft.toRequestBody()` builds the save payload.
- **Parse pipeline** (`Parse` in `parser.go`): `splitLines` (also applies `fixTurkishGlyphs`) → amount/date/merchant/merchant-category → `extractSummary` (`summary.go`) → `extractItemsWithBare` → `resolveTotal` → `recoverBareAmounts` → `reconcile` (`reconcile.go`) → `applyCategories` (item + receipt category). Summary/info lines (TOPLAM, ARA TOPLAM, KDV, İNDİRİM, NAKİT, KART, PARA ÜSTÜ…) are classified in `summary.go` and never become items; short labels match whole words only (so "kart" doesn't drop KARTON SÜT). Quantity lines (`qtyPrefixRe`) use the rightmost amount as the net line total — OCR rows are ordered by x, so "last amount on the line" = largest X. Reconciliation only deletes an item with duplicate evidence (adjacent same item); otherwise it flags `needs_review` and reports a suspect. Response extras: `discount_total` (mobile saves `items − discount_total`, since item amounts must be ≥ 0), `summary`, `reconciliation` (documented in `docs/openapi.yaml`).
- **Turkish glyphs:** PaddleOCR maps `lang=tr` to `latin_PP-OCRv3_rec`, whose `latin_dict.txt` has no ş/Ş/ğ/Ğ/İ but does have `$`, so Ş comes out as `$` (Fİ$, KA$AR) — no config flag fixes this. The fix is post-processing, implemented three times and kept identical: Python `postprocess.fix_turkish_glyphs` (per block, before `dedupe_blocks`), Go `fixTurkishGlyphs` and Dart `fixTurkishGlyphs`; all three test suites read the same vectors from the repo-root `testdata/` (see its README: `glyphs.json`, `rows.json`, `merge.json`, `parse/*.json`, `merchant_brands.json`; Python tests need `-v <repo>/testdata:/testdata` in the docker run, otherwise they skip). `$` immediately before a digit is a price-column marker and must stay (the parser's regexes rely on it). The engine reports the loaded rec model/dict and missing letters in OCR `metadata` (`rec_*`).
- The same Strategy pattern is mirrored in **expense** (`ocr_engine.go`: `OcrEngine` interface, `RemoteMicroserviceOcrEngine` delegating to `OCR_SERVICE_URL`, factory from env) and in the **mobile** app (`lib/ocr/ocr_engine.dart`). Adding an OCR engine means touching these layers consistently; the JSON shape (`raw_text`, `blocks`, `confidence`, `engine`, `model_version`, `elapsed_ms`) is shared across all three.
- **Mobile** (Flutter, plain `ChangeNotifier`-style state in `app_state.dart`, no heavy framework): `api.dart` is the single HTTP client (auth :8081, expense :8082; the client never calls OCR directly, scans go through expense `POST /receipts/scan`; host is `10.0.2.2` on Android emulator, else `localhost`; injectable `http.Client` for tests). It attaches the access token, refreshes it silently (single-flight; one retry after a 401, multipart requests are rebuilt; a *network* failure during refresh keeps the session, a rejected refresh ends it via `onUnauthorized`) and refreshes ahead of expiry (`ensureFresh`, also called by an `AppState` timer and on app resume because `Image.network` reads `authHeaders` synchronously). Tokens live in `flutter_secure_storage` (`auth_tokens`, `auth_user`); **no passwords are stored** and the old `profiles_v2`/`jwt`/`active_profile_v2` keys (synthetic `p_*@fissio.local` accounts) are wiped on startup. **Profiles are server-side now** (`Profile.id` = `client_uid`); `AppState.logout`/sign-in `_resetMemory()` clears user, profiles, expenses, categories and active profile (`active_profile:<userId>` key). **Cloud sync** (`sync_enabled:<userId>`, default ON): with sync ON a failed *network* call queues the receipt/profile/photos in the device store as `SyncState.pending` and `SyncService.flush()` (`data/sync_service.dart`) uploads them idempotently (profiles → `/expenses/bulk` → photos; a rejected receipt only stays queued with `Expense.syncFailures/syncError` — the rest and the later steps still run; a rejected multi-item batch is retried one by one; `skipped` receipts whose local copy was edited meanwhile are PUT (`SyncService.sameContent`); photos are given up after `maxImageFailures`; `AppState.refresh` and `flushNow` are serialized by `_exclusive` — a Completer queue on purpose, a Future chain deadlocks when `runAsync` and FakeAsync zones mix in tests — and `flushNow` backs off 60 s→15 min exponentially and only re-downloads when something progressed (`_needsRefresh`); a flush aborts if the account/sync switch changed mid-run) on connectivity change (`ConnectivityMonitor`), app resume, any successful API call, sign-in or toggle; 4xx validation errors are never queued. With sync OFF nothing is ever written to the server (`SyncState.localOnly`; cloud receipts become read-only; OCR scan still sends the photo transiently); turning sync on converts local-only → pending and flushes, turning it off converts pending → local-only. Device data (`data/local_store.dart`, per-user JSON + image files via `path_provider`, `MemoryLocalStore` in tests) survives logout and is deleted on account deletion; local receipts have negative ids. Export/import is pure Dart in `data/data_transfer.dart` (JSON `fissio-backup` v1 / CSV `;` + BOM, auto-detects delimiter and decimal separator, validates, de-duplicates by `client_uid` OR a content fingerprint) with `data/file_transfer.dart` (share_plus/file_picker) behind an interface.
