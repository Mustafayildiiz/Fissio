# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Fissio: smart receipt processing and micro-expense management (Turkish-language UI/comments). Monorepo with three backend microservices (Docker Compose) and a Flutter mobile app. Note: README.md is in a legacy (non-UTF-8) encoding — don't edit it with Edit/Write.

## Commands

Backend (repo root; copy `.env.example` to `.env` for config, defaults work for dev):
- `docker compose up --build` — starts postgres, auth (host :8081), expense (:8082), ocr (:8083). Postgres is internal-only (not exposed). Schema comes from `db/init.sql` (runs only on first volume init).
- Go services (`services/auth`, `services/expense`, Go 1.25, gin + lib/pq + golang-jwt): from the service dir, `go test ./...`; single test: `go test -run TestName ./...`. Both have tests (`auth`: `unit_test.go` + PG-gated `auth_pg_test.go`; `expense`: `*_test.go`; `realreceipts_test.go` holds real PaddleOCR outputs whose assertions — e.g. BIM Koltuk = 17 items, PATITO ×2, no review — lock in deliberate parser behaviour). `integration_pg_test.go` (migration + HTTP flow incl. learned rules) is skipped unless `FISSIO_TEST_DATABASE_URL` points at a throwaway Postgres whose URL contains "test" — it DROPs the `expense` schema (e.g. `docker run -d -e POSTGRES_PASSWORD=t -e POSTGRES_DB=fissio_test -p 55432:5432 postgres:16-alpine`, then `FISSIO_TEST_DATABASE_URL=postgres://postgres:t@localhost:55432/fissio_test?sslmode=disable go test -run PG ./...`). The PG-gated suites (`auth_pg_test.go`, `integration_pg_test.go`, `isolation_pg_test.go`) all use the same `FISSIO_TEST_DATABASE_URL` and each DROPs the `auth` and/or `expense` schemas, so run the auth and expense suites one after the other, never in parallel. They create minimal copies of the other service's tables with raw DDL (`expense.*` in the auth test, `auth.sessions` in the expense test) because the modules cannot import each other.
- OCR service (`services/ocr`, Python 3.11, FastAPI): `pytest tests/`; run locally with `uvicorn app:app --port 8080`. Tests don't need paddleocr (imported lazily) but need numpy/opencv; the host Python usually lacks them, so run them in the built image with the source mounted: `docker run --rm -v "<repo>/services/ocr:/app" -w /app fissio-ocr:latest python -m pytest tests/ -q -p no:cacheprovider` (Git Bash: prefix `MSYS_NO_PATHCONV=1`, use `$(pwd -W)`). The image bakes code in via `COPY`, so the running service only picks up changes after `docker compose up --build`.

Mobile (`fissio_mobile/`): `flutter pub get`, `flutter run`, `flutter test`, single test: `flutter test test/ocr_engine_test.dart`, `flutter analyze`. Don't run `dart format` on existing files: the code is written with ~100-column lines and no formatter `page_width` is configured, so it reflows whole files to 80 columns.

## Architecture

- **auth** (Go, files `config/jwt/otp/mailer/sessions/ratelimit/account/handlers/main.go`): register → 6-digit email OTP (`auth.email_otps`, HMAC-hashed, 10 min `OTP_TTL_MINUTES`, ≤5 attempts, 60 s resend cooldown, ≤5/hour) → `verify-email` opens the first session; an unverified account cannot log in (login answers `403 email_not_verified` and re-sends a code only when the password was right). Tokens: 15-minute access JWT (`sub`, `sid`, `typ=access`, `JWT_ACCESS_SECRET`, falls back to `JWT_SECRET`) + opaque 30-day refresh token stored HMAC-hashed (`JWT_REFRESH_SECRET`) in `auth.refresh_tokens`, rotated on every use; a used token presented after a 45 s grace window revokes the whole session (theft detection). `auth.sessions` tracks device/platform/last activity; endpoints: `refresh`, `logout`, `logout-all`, `GET /auth/sessions`, `DELETE /auth/sessions/:id`, `forgot-password` (always 202) / `reset-password` (code, revokes all sessions), `DELETE /auth/account` (password confirmation; one transaction deletes `expense.*` rows — guarded by `to_regclass` — and all `auth.*` rows). Mail: `Mailer` interface, SMTP via `SMTP_HOST/PORT/USER/PASS/FROM`; **empty `SMTP_HOST` = dev fallback that logs the code** (`docker compose logs auth | grep DEV-OTP`; codes are never returned by the API). In-memory per-IP limiter (`handler.rateMax`, tests raise it). Existing users are treated as verified by `migrate()` (backfill happens only when `email_verified_at` is first added). Schema lives in `migrate()` (`db/init.sql` only creates the schemas).
- **expense** (Go): validates the access JWT itself (`jwt.go`; no HTTP call to auth — `JWT_ACCESS_SECRET`/`JWT_SECRET` must match) and checks that its `sid` is not revoked in the shared Postgres `auth.sessions` (`sessionChecker`, 10 s cache, 503 `auth_unavailable` if the table does not exist yet), so logout/remote logout/account deletion take effect within ~10 s instead of at token expiry. **User → Profiles → Receipts**: `expense.profiles(user_id, name, client_uid)`, `expenses.profile_id` (BIGINT FK, the old unused text column is kept as `profile_id_legacy`) and `expenses.client_uid` (UNIQUE per user; existing rows got `srv-<id>`). `GET /profiles` creates the default "Kişisel" profile under an advisory lock when the account has none; every query is scoped by `user_id` and cross-account/profile access returns 404. `POST /expenses` is idempotent on `client_uid` (200 + existing row); `POST /expenses/bulk` (≤500, per-item `created|skipped|error`) serves the offline queue and backup import. `profile_id` is optional on create (default profile) and filters list/summary. Routes at the root (no `/api` prefix) in `main.go`: categories, `receipts/parse` (text → structured fields via `parser.go`), `receipts/scan` (multipart, repeated `file` = pages of one long receipt, ≤6 pages/≤5MB each → OCR per page → `mergePageTexts` in `merge.go` (drops a seam only when ≥2 consecutive lines match: amounts must be identical, text matches via Levenshtein, Jaro-Winkler or left-cropped suffix) → one parse), expenses CRUD, `expenses/:id/images` (upload/get/delete receipt photos, stored as bytea in `expense.receipt_images`, ownership checked via JOIN on the expense's `user_id`), `reports/summary`. Direct `database/sql` access in `db.go`/`handlers.go`; CORS handled by hand in `main.go`.
- **ocr** (Python): receipt OCR using Strategy + Factory Registry (`ocr/base.py`, `factory.py`, `paddle_engine.py`, `custom_engine.py`, `config.py`). Engine chosen per request via `?engine=`, `X-OCR-Engine` header, or `OCR_ENGINE` env (default `paddleocr`, PP-OCRv4 mobile, `OCR_LANG=tr`). Endpoint: `/ocr/extract` (base64 image JSON, also multipart). Post-processing in `postprocess.py`: glyph fix, `dedupe_blocks` (NMS on overlapping same-text boxes, plus dropping fragment boxes contained in a full-line box), then `paddle_engine._reconstruct_receipt_lines` groups blocks into rows (slope-corrected) and orders each row left-to-right.
- **Auto-categorization** (`categorizer.go`, `category_lexicon.go`, `rules.go`): hybrid, pure functions, run inside `ParseWith` (`Parse` = `ParseWith` with no options). Taxonomy is the fixed 11-category set seeded/migrated in `db.go` (`migrateTaxonomy` renames the old names and merges Ulaşım into Akaryakıt / Ulaşım); the engine keys everything on `catKey` via `categoryKeyOf(name)` so old and new category names both work. Merchant layer: user rule (0.98) > header brand (0.9) > body-only brand (0.6); brands come from the code lexicon plus the `categories.keywords` column (`enrichCats`). Item layer (`classifyItem`): user item rule > lexicon (exact 0.9 / suffix-tolerant prefix 0.8 / truncated 0.7 / fuzzy 0.65; ties broken by a confident merchant context, e.g. ÇAY at a café vs market) > inherit the confident merchant's category (0.6, source `merchant`) > `Diğer` + `category_review`. Receipt category: confident merchant (≥0.85) wins even for mixed receipts (items keep their own categories), otherwise weighted vote (`amount × confidence`, × coverage, cap 0.85), below `categoryMinConfidence` (0.5, env `CATEGORY_MIN_CONFIDENCE`) falls back to `Diğer` with `category_needs_review` (separate from the total-mismatch `needs_review`). Learning: `POST/PUT /expenses` accept `suggested_category_id` (receipt and per item); when it differs from the saved `category_id`, `collectRuleUpdates` upserts a per-user row in `expense.category_rules` in the same transaction (keys from `merchantKey`/`normalizeKey`, ≤2000 per user); `loadRules` feeds them back into `ParseWith`; `GET /category-rules`, `DELETE /category-rules/:id`. Items persist only `{name, amount, category_id}` in the JSONB (`itemsForStorage`). Mobile: the draft keeps the scan's suggestion (`suggestedCategoryId`), `ReceiptDraft.toRequestBody()` builds the save payload.
- **Parse pipeline** (`Parse` in `parser.go`): `splitLines` (also applies `fixTurkishGlyphs`) → amount/date/merchant/merchant-category → `extractSummary` (`summary.go`) → `extractItemsWithBare` → `resolveTotal` → `recoverBareAmounts` → `reconcile` (`reconcile.go`) → `applyCategories` (item + receipt category). Summary/info lines (TOPLAM, ARA TOPLAM, KDV, İNDİRİM, NAKİT, KART, PARA ÜSTÜ…) are classified in `summary.go` and never become items; short labels match whole words only (so "kart" doesn't drop KARTON SÜT). Quantity lines (`qtyPrefixRe`) use the rightmost amount as the net line total — OCR rows are ordered by x, so "last amount on the line" = largest X. Reconciliation only deletes an item with duplicate evidence (adjacent same item); otherwise it flags `needs_review` and reports a suspect. Response extras: `discount_total` (mobile saves `items − discount_total`, since item amounts must be ≥ 0), `summary`, `reconciliation` (documented in `docs/openapi.yaml`).
- **Turkish glyphs:** PaddleOCR maps `lang=tr` to `latin_PP-OCRv3_rec`, whose `latin_dict.txt` has no ş/Ş/ğ/Ğ/İ but does have `$`, so Ş comes out as `$` (Fİ$, KA$AR) — no config flag fixes this. The fix is post-processing, implemented twice and kept identical: Python `postprocess.fix_turkish_glyphs` (per block, before `dedupe_blocks`) and Go `fixTurkishGlyphs`; both test suites share the same vectors. `$` immediately before a digit is a price-column marker and must stay (the parser's regexes rely on it). The engine reports the loaded rec model/dict and missing letters in OCR `metadata` (`rec_*`).
- The same Strategy pattern is mirrored in **expense** (`ocr_engine.go`: `OcrEngine` interface, `RemoteMicroserviceOcrEngine` delegating to `OCR_SERVICE_URL`, factory from env) and in the **mobile** app (`lib/ocr/ocr_engine.dart`). Adding an OCR engine means touching these layers consistently; the JSON shape (`raw_text`, `blocks`, `confidence`, `engine`, `model_version`, `elapsed_ms`) is shared across all three.
- **Mobile** (Flutter, plain `ChangeNotifier`-style state in `app_state.dart`, no heavy framework): `api.dart` is the single HTTP client (auth :8081, expense :8082, ocr :8083; host is `10.0.2.2` on Android emulator, else `localhost`; injectable `http.Client` for tests). It attaches the access token, refreshes it silently (single-flight; one retry after a 401, multipart requests are rebuilt; a *network* failure during refresh keeps the session, a rejected refresh ends it via `onUnauthorized`) and refreshes ahead of expiry (`ensureFresh`, also called by an `AppState` timer and on app resume because `Image.network` reads `authHeaders` synchronously). Tokens live in `flutter_secure_storage` (`auth_tokens`, `auth_user`); **no passwords are stored** and the old `profiles_v2`/`jwt`/`active_profile_v2` keys (synthetic `p_*@fissio.local` accounts) are wiped on startup. **Profiles are server-side now** (`Profile.id` = `client_uid`); `AppState.logout`/sign-in `_resetMemory()` clears user, profiles, expenses, categories and active profile (`active_profile:<userId>` key). **Cloud sync** (`sync_enabled:<userId>`, default ON): with sync ON a failed *network* call queues the receipt/profile/photos in the device store as `SyncState.pending` and `SyncService.flush()` (`data/sync_service.dart`) uploads them idempotently (profiles → `/expenses/bulk` → photos) on connectivity change (`ConnectivityMonitor`), app resume, any successful API call, sign-in or toggle; 4xx validation errors are never queued. With sync OFF nothing is ever written to the server (`SyncState.localOnly`; cloud receipts become read-only; OCR scan still sends the photo transiently); turning sync on converts local-only → pending and flushes, turning it off converts pending → local-only. Device data (`data/local_store.dart`, per-user JSON + image files via `path_provider`, `MemoryLocalStore` in tests) survives logout and is deleted on account deletion; local receipts have negative ids. Export/import is pure Dart in `data/data_transfer.dart` (JSON `fissio-backup` v1 / CSV `;` + BOM, auto-detects delimiter and decimal separator, validates, de-duplicates by `client_uid` OR a content fingerprint) with `data/file_transfer.dart` (share_plus/file_picker) behind an interface. Screens in `lib/pages/` (restyled from the "Fissio Hesap" design): `auth_page.dart` (login/register), `verify_email_page.dart` (6-box OTP + countdown), `forgot_password_page.dart` (code-based reset), `account_ready_page.dart`, `sessions_page.dart`, `data_management_page.dart` (sync switch, export, import), account section + delete-account in `settings_page.dart`; shared pieces in `account_widgets.dart`. Scan flow in `scan_page.dart` (a capture session of up to 6 pages via `ScanSession`; camera adds a page, gallery allows multi-select) → `receipt_form_page.dart` (receipt fields and line items on one screen). Photos stay in memory as `ReceiptDraft.pendingImages` until `AppState.saveDraft` uploads them (or writes them to the device queue); `receipt_detail_page.dart` shows them (`receipt_images.dart`: JWT-authenticated `Image.network` for cloud photos, `Image.memory` for device photos). UI is themed via `lib/theme.dart` (`FissioColors` ThemeExtension, light/dark, `context.c`; Archivo font; Lucide icons) and user preferences (accent colour, theme mode, receipt-detail style) live in `theme_controller.dart`; shared widgets are in `widgets.dart`, dashboard maths in `stats.dart`. Tests construct `AppState`/`ApiClient` with injected fakes (`test/support/fake_backend.dart`: in-memory server with offline switch, request log, MemPrefs/FakeConnectivity); widget tests that need async I/O wrap the setup in `tester.runAsync`. **Onboarding:** `pages/onboarding_page.dart` (3 adım, yalnızca `FissioColors` tokenları) is shown only after a *sign-up* in `AuthPage._submit` (before `ProfileSelectPage`); login/`restoreSession` never show it. State lives in `onboarding_controller.dart` (injectable `PrefsStore`, global `onboardingController`): `onboarding_seen:<email>` suppresses auto-show only; the Settings row "Tanıtım Rehberini Görüntüle" is **always visible** (the old device-wide `onboarding_replay_used` flag hid it for good after one use and is no longer read). The guide closes with `Navigator.pop()` (not `maybePop`, which its page-back `PopScope` would turn into "previous step"). **Support/About/Privacy:** `pages/info_page.dart` (`InfoTexts` = lists of `InfoSection`), `pages/support_page.dart` (mailto via `app_info.dart`: `supportEmail`, injectable `mailLauncher`/`clipboardWriter`/`appVersionLoader`, FAQ, version from `package_info_plus`). **Profile avatars** are per expense profile: expense `expense.profiles.avatar/avatar_type/avatar_version` + `PUT|GET|DELETE /profiles/:id/avatar` (`avatar.go`, ≤1 MB, type sniffed; `avatar_version` is 0 when none and bumps on every upload for `?v=` cache busting); mobile `Profile.avatarVersion`/`localAvatarPath`, `AppState.setProfileAvatar/removeProfileAvatar` (sync ON + online → upload; sync OFF/offline → device file that `SyncService` step 1b uploads later), `profile_avatar.dart` (`ProfileAvatarView`, initials fallback) and `pages/avatar_picker.dart` (client downscale 512px/q80). **On-device OCR:** `ocr/on_device_ocr_engine.dart` (ML Kit Latin behind `TextRecognizerPort`; `reconstructRows` groups boxes into rows; `fixTurkishGlyphs` on raw text) + `receipt_parser/` (Dart port of Go `normalize.go`/`parser.go`/`summary.go`; NOT ported: categorizer, `recoverBareAmounts`, `reconcile`/`resolveTotal` → category `Diğer` + review flags, dropped bare amounts, so e.g. BIM Koltuk yields 15 items + `needsReview` instead of 17). `AppState.scanAndParseReceipt` follows `themeController.ocrMode` (`OcrMode.auto|server|onDevice`, key `pref_ocr_mode`, Tercihler > "Fiş okuma"): sync OFF always forces device OCR (the photo never leaves the phone, whatever the mode), otherwise auto = server only when online, `server` = server, `onDevice` = device; any network failure of the server call falls back to device OCR. The device engine is not in `ocrFactory`. The server engine (`paddleocr`/`custom`) is chosen in Tercihler > "Sunucu OCR motoru" (`themeController.ocrEngine`, key `pref_ocr_engine`, labels via `ocrEngineLabel`); the scan page no longer has an engine picker. The "+" (Yeni fiş) in `shell_page.dart` opens `ScanPage` directly; manual entry is the Manuel switch on the scan page.
- **Budgets / recurring expenses / widget / brand** (added together): **Backend** `budgets.go` (`expense.budgets(user_id, profile_id FK CASCADE, category_id, monthly_limit)`, UNIQUE per profile+category; `GET/PUT /budgets`, `DELETE /budgets/:id`; `spent` = receipt `amount` summed per receipt category for the month, `status` ok/warning(>=80%)/exceeded(>=100%) on integer cents) and `recurring.go` (`expenses.recurring_day` 1-31 / `recurring_remind`; `GET /recurring`; **series dedupe**: key = category + folded merchant per profile, the latest receipt wins, an unmarked latest receipt ends the series, so Jan+Feb electricity are counted once; next due clamps day 31 to month length and rolls to next month when this month already has a receipt). `recurring_*` are carried by `POST/PUT /expenses`, **`/expenses/bulk`** (offline queue + import), list/get JSON and the JSON backup. Account deletion removes `expense.budgets` (auth `account.go`, also in `auth_pg_test.go` DDL). `budgets_pg_test.go` covers account/profile isolation. **Mobile**: pure logic in `budgets.dart` (`budgetLevel`, `computeBudgetProgress`, `evaluateBudgetAlerts`: each 80/100 threshold notifies once per month+profile+category, a receipt crossing both sends only the 100 one, keys persisted in prefs `budget_alerts:<uid>`) and `recurring.dart` (Dart twin of `recurring.go`, `planReminders` = 3 days before + due day at 09:00 local); `AppState.setBudget/removeBudget` (cloud / pending queue / localOnly like receipts, stored in `LocalSnapshot.budgets`, flushed by `SyncService` step 3), `_checkBudgets(receipt's profile)` after `saveDraft`, `recurring`, `upcomingPayments`. Side effects are injectable ports (`services/notifier.dart` `LocalNotifier`, `widget_sync.dart` `WidgetSync`, `launcher_icon.dart`, `deep_links.dart`); `AppState.notifyListeners` is overridden to push the widget payload (active profile's calendar-month total) and reschedule reminders only when they changed, and `_localSignOut` clears widget data + cancels all notifications. UI: `pages/budget_widgets.dart` (`BudgetBar`: accent / `c.warn` yellow / `c.danger` red), `budgets_page.dart`, `recurring_page.dart`, form switch "Her ay tekrarlanır" in `receipt_form_page.dart`. **Brand/theme**: `theme.dart` `kBrandPalette` = the 7 colours of the "Fissio Logo Final" design (also `kAccentOptions`; default accent is the brand red #EC3013; near-black accents get a light fill in dark mode), `logo.dart` (`FissioLogoPainter`, `FissioLogo`, the receipt-on-tile logo), `ThemeController.logoOverride` (null = logo follows accent; key `pref_logo`) which also switches the launcher icon (Android: `MainActivity` = red + 6 disabled `activity-alias`es toggled by `MainActivity.kt`, **release/profile builds only** — disabled when debuggable because a non-red icon disables `MainActivity` and breaks `flutter run`; iOS alternate icon sets). Regenerate launcher PNGs with `flutter test tool/generate_icons_test.dart`. Android widget = `FissioWidgetProvider.kt` + `res/layout/fissio_widget.xml`; its "Fiş tara" button opens `fissio://scan`, consumed by `ShellPage` via `DeepLinkController` (pending until session + profile are ready; `SplashPage` skips profile selection for it). The iOS widget (`ios/FissioWidget/`) is source only and unverified. Android needs `compileSdk 37` + core-library desugaring (flutter_local_notifications 23).
  **Follow-ups** (all covered by tests): (1) *Reactivity*: `BudgetsSection`/`FixedExpensesSection` wrap their own `build` in a `ListenableBuilder` because `home_page.dart` passes them as `const` (a const child is never rebuilt by the parent's `ListenableBuilder`; only theme changes via InheritedWidget did) — same trap as `_LogoSection`. (2) *Total monthly budget*: `expense.budgets.category_id` is nullable, NULL = the profile's total budget (partial unique index `uq_budgets_total`; `PUT /budgets` without `category_id`); mobile uses `kTotalBudgetCategoryId = 0` (`Budget.isTotal`), spent = all categories of the month, listed first, same 80/100 thresholds and alerts. (3) *Offline-first*: `LocalSnapshot.cloudExpenses` is a read-through cache of the last server fetch (separate from `expenses` = the upload queue; dropped from disk on sign-out, unsynced data stays); `AppState._cloudExpenses` is a view = cache + `pendingEdits` (offline edits of server receipts, flushed with `PUT`) − `pendingDeletes` (flushed with `DELETE`); `pendingBudgetDeletes` are budget tombstones; a network failure in `refresh()` sets `offline` (soft `OfflineBanner`), not `error`. (4) *Fixed vs variable recurring*: `expenses.recurring_kind` (`fixed|variable`) + `recurring_estimate`; variable bills project the moving average (min–max) of the last 3 months (one receipt per month), else the estimate, else the last amount; a series with a receipt in the current month is `paid_this_month` and the projection uses the real amount (`monthly_total` = paid actual + unpaid expected; also `paid_total/remaining_total/min_total/max_total`). The receipt form pre-fills "Her ay tekrarlanır" from a matching active series (`AppState.seriesFor`) so a new month's bill continues the series. Go (`recurring.go`) and Dart (`recurring.dart`) share test vectors (`recurring_test.go` ↔ `recurring_variable_test.dart`). (5) *Widget*: RemoteViews only inflates allowed classes — never `<Space>`/`<View>` in `fissio_widget.xml` (use `FrameLayout`); `MainActivity.onNewIntent` calls `setIntent` so `fissio://scan` survives a singleTop relaunch / killed process; the provider renders "0,00 ₺" when the app never wrote data.
